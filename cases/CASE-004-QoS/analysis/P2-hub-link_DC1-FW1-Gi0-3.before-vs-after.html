Next steps

  1. Check output drops on the egress interface toward the receiver; tail drops during bulk bursts mean the queue is too small or unprioritized. (Heavy packet loss on 10.1.40.10:9000)
  2. Look for duplex/speed mismatch and CRC/input errors on both ends of the link (a bad optic or cable shows as CRC). (Heavy packet loss on 10.1.40.10:9000)
  3. Compare retransmission rate per DSCP/class if QoS is configured: loss limited to one class is policy, loss everywhere is congestion or physical. (Heavy packet loss on 10.1.40.10:9000)

Method and definitions

How numbers are made. Every figure comes from tshark dissection of the capture (the same engine as Wireshark), aggregated by this tool. The AI review, when enabled, only explains these numbers and is checked against them.

  • Client-felt time: first request byte to the client's ACK of the first response segment, so dropped and resent replies count.
  • Server think: last request byte to first response byte. Fast think plus slow client-felt means the network path.
  • Stall: first send to last resend of the same segment.
  • Artifacts: things caused by where/when the capture started or stopped. Listed, never counted as failures.
  • Capture point matters: timings are as seen at the capture location; a second capture at the other end pinpoints the hop.
